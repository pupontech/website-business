# Astro + Ghost Website Business

Planning and delivery repository for a lean website business specializing in:

1. Custom Astro websites with a project-appropriate CMS.
2. Ghost publications, setup, migrations, and custom themes.
3. Hosting and maintenance where the responsibility and margin are commercially justified.

The immediate goal is a viable service business, not a proprietary builder, multi-tenant platform, custom CRM, or speculative internal tooling.

## Working principles

- Sell customer outcomes; frameworks are implementation choices.
- Prefer managed services when they reduce operational risk at a sensible total cost.
- Keep each client’s repository, credentials, CMS instance, and deployment isolated.
- Optimize for client ownership, portability, security, accessibility, performance, and maintainability.
- Use AI-assisted delivery with bounded tasks, independent review, and human approval gates.
- Cite current primary sources and distinguish sourced facts, estimates, and recommendations.
- Never fabricate clients, testimonials, prices, results, or completed tests.

## Repository map

- `AGENTS.md` — non-negotiable project and delegation rules.
- `PROJECT_STATUS.md` — current state, complete backlog, dependencies, gates, blockers, and next task.
- `DECISIONS.md` — approved and provisional architecture/business decisions with sources.
- `docs/` — verified phase deliverables; files are created only when substantive work exists.
- `research/` — scoped source notes and subagent research artifacts used in synthesis.
- `openspec/` — OpenSpec policy and future significant implementation changes.

## Resume protocol

When instructed to **continue**:

1. Read `AGENTS.md`, `PROJECT_STATUS.md`, and relevant accepted deliverables.
2. Inspect the active Kanban board and repository state.
3. Select only the next task whose dependencies and approval state permit it.
4. Avoid repeating accepted research unless a source is stale or a verification gap is recorded.
5. Update `PROJECT_STATUS.md` and the Kanban card at task completion.

## Current scope

Project initialization and Phase 1 research are authorized. Production implementation, paid services, domains, DNS, and public deployment are not authorized.
