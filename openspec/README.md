# OpenSpec workflow

OpenSpec changes are required for significant implementation work after the relevant approval checkpoint.

Each change directory must contain substantive artifacts defining:

1. Problem and proposal.
2. In-scope and out-of-scope behavior.
3. Requirements and affected contracts/content models.
4. Design and security implications.
5. Ordered implementation tasks with file ownership.
6. Acceptance criteria and verification commands.
7. Links to applicable entries in `DECISIONS.md`.

Research-only documents and small editorial fixes do not require a change. No implementation change may use this directory to bypass Checkpoint 1, Checkpoint 2, or Checkpoint 3.
